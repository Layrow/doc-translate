# 翻译规范模板(复制到项目工作区并填充)

> 使用方法:复制本文件到目标项目工作区(如 `TRANSLATION_GUIDE.md`),把 `<...>` 占位符
> 替换为实际路径与项目术语,然后所有翻译子智能体都必须先 Read 本文件再工作。
> 本模板源自 Apache Paimon 文档翻译实战,结构经过验证。

# <项目名> <目标语言> 文档翻译规范

每个翻译子智能体必须严格遵循本规范。目标:高质量、术语统一的译文。

## 1. 路径约定

- 源文件:`<项目工作区>/<源目录相对路径>`
- 目标文件:`<项目工作区>/<目标目录相对路径>`
- 目标路径必须完整镜像源路径(含子目录),文件名**保持不变**。
- 一次性任务:Read 源文件 → 按规范全文翻译 → Write 到目标路径。

## 2. 硬性规则(必须原样保留,禁止翻译/改动)

1. **License/版权头注释块**:文件开头 `<!--` 到 `-->` 的许可证注释原样保留。
2. **代码块**:所有 ``` 围栏代码块(含其中的注释)完全原样,一个字符都不改。
3. **行内代码** `` `code` ``:命令、SQL、配置项、路径、类名原样保留。
4. **frontmatter**:YAML 结构与除 title/description 外的所有字段原样保留;仅 `title` 与 `description` 的值译成中文(引号风格保持)。`sidebar_label` 同样只译值(若项目惯例需要)。
5. **MDX/JSX 语法**:`import` 语句、组件标签(`<Tabs>`/`<TabItem>`/自定义组件)、`{...}` 表达式原样保留;组件标签**之间的**正文文字翻译。
6. **变量插值 token**:`@@VERSION@@`、`{{placeholder}}`、`$VAR` 等原样保留,不得翻译或改写。
7. **标题锚点**:形如 `## Heading {#custom-anchor}` 的 `{#...}` 部分原样保留,只译 Heading 文字。
8. **`<!-- truncate -->` 等框架标记**:原样保留。
9. **链接**:URL、相对路径、锚点一律不变;只翻译链接显示文字。
10. **HTML 标签**:`<center>`、`<details>` 等标签与属性原样,标签间文字翻译。
11. **admonition 语法**:`:::note`、`:::warning [Title]` 等——标记原样;英文标题可译(如 `:::note 注意`);`:::` 结束标记原样。
12. **数字、版本号、配置键名、SQL 关键字、URL、邮箱**:不变。
13. **空行结构**:尽量保持段落/列表结构与原文对齐,不要合并或拆分段落(下游自动合并依赖块级对齐)。

## 3. 术语表(必须统一)

### 3.1 保留英文不译(按项目填充)

<列出:产品名、框架名、协议名、格式名、类名、核心机制名。例:Paimon、Flink、Catalog、Compaction、Changelog、LSM、ORC/Parquet>

### 3.2 固定译法(首次出现可括注英文,之后用中文)

| 英文 | 中文 |
|------|------|
| <核心概念 1> | <译法> |
| <核心概念 2> | <译法> |

<按项目领域填 30~80 条高频术语;技术社区已有通用译法的优先采用(如 Flink 中文文档惯例)>

### 3.3 未收录术语

按"技术社区通用译法 + 首次出现括注英文"处理;拿不准的保留英文。

## 4. 风格指南

- 使用**简体中文**书面语,面向目标读者(数据工程师/开发者),语气客观、简洁、专业。
- 不逐词硬译:先理解句子含义,再用地道中文重述;但**不得增删技术含义**。
- 英文长句拆成短句;被动语态改为主动。
- 列表项、表头、界面文字都要翻译(除规则 2 保留者)。
- 标题翻译保持层级与序号不变。
- 中英文之间加一个空格;全角标点(,。:;),括注内容全为英文/数字时可用半角括号。
- 表格中的文字译,键名/代码不译。
